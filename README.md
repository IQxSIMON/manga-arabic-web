# Manga Arabic Translator

An early local-first web prototype for English-lettered vertical comics translated into Arabic. It is organized around a continuous top-to-bottom reading stream, regardless of the work's country of origin or publisher. Online source adapters include MangaDex and experimental ManhuaPlus.org discovery/import. OCR is local by default; optional Google Vision and OCR.space integrations remain separate from translation.

## Current development scope (2026-11-08)

- The active web workflow is defined by reading layout, not origin: English-lettered vertical comics (including vertical Manhwa and Manhua) are read top-to-bottom and left-to-right, then translated into Arabic. MangaDex discovery no longer restricts origin country and only lists English chapters; ManhuaPlus remains experimental and records its declared comic type.
- The web form requires the user to identify the chapter layout before import or translation. Continuous vertical scrolling is supported; page-by-page layouts show an unsupported notice and are rejected before remote fetch, OCR, or import. Layout is not inferred from origin or title, and the server rejects missing or non-vertical layout declarations on import, fetch, translation, and rendering APIs.
- Index-Translate-9B is the only translation engine exposed by the application. OPUS, MADLAD, Qwen, and TranslateGemma code and old data remain in the repository for compatibility/history, but are not selectable as the current web translation engine.
- The translation panel reports whether the Index weight file and llama.cpp executable are present and shows their expected locations. Presence is not treated as proof of successful model inference.
- OCR remains local and modular: RapidOCR recognizes lettering, and an optional pinned RT-DETR model proposes comic text regions to help recover missed speech/narration text. Existing bubble segmentation still controls bubble association and image repair; rectangular detector boxes never authorize erasing pixels.
- Clear English captions outside bubbles are in scope for vertical comics, while standalone sound effects and non-English lettering are not. Exterior-text recognition and style-preserving rendering are experimental and need visual review on more licensed samples.
- The detector's 11.1 MB INT8 ONNX artifact is locally ignored by Git and documented at [`translator_engine/models/comic_text_detector/README.md`](translator_engine/models/comic_text_detector/README.md). Its upstream model card reports Apache-2.0; this project has only checked a small visual sample and does not claim a measured chapter-wide accuracy improvement.
- The bullets below record incremental and historical behavior. When they mention other engines, broader comic types, or older prompt/pipeline versions, the current scope above takes precedence.

## Current status

- A tilted external quest panel in a saved page exposed two issues: page OCR had missed two lines and text-style estimation made white source lettering black. Skewed external groups now get a bounded, enlarged deskew retry and replace the first pass only when the retry adds substantially more text at comparable confidence; renderer color estimation uses local contrast and the new OCR polygons for cleanup. On that sample crop the retry recovered 5 lines at 0.89–0.98 confidence, and a render preview removed the recognized English and typeset white outlined Arabic without overlap. This is a targeted visual check; the app still needs to reprocess that page with the updated OCR and translation prompt before the recovered full text is validated end to end.
- The application can list remote chapter images and request OCR/translation. The local path segments speech bubbles and runs RapidOCR inside them. For vertical chapters it also scans overlapping page tiles for clear English outside bubbles, keeps OCR quadrilaterals and rotation, excludes text already assigned to balloons, and conservatively skips common standalone all-caps sound effects. Google Vision and OCR.space remain optional legacy OCR choices.
- External-text OCR uses a stricter 0.55 minimum confidence than bubble OCR (which retains the configured local threshold), to reduce inaccurate lettering replacement over artwork. This precision/recall change invalidates the saved page OCR pipeline; its effect has not yet been measured on a representative chapter.
- Saved page results now advance to pipeline version 19 after the skewed-caption OCR refinement, so pages processed by the prior OCR are detected as stale. On refresh, exact matching preserves user-reviewed Arabic and manual exclusions while adopting new OCR geometry. Regression coverage verifies both behaviors; the current-code visual page check is queued behind the ongoing full-chapter inference.
- Bubble and external OCR now reject non-finite confidence scores and malformed/non-finite coordinates before processing. External OCR also rejects text when more than 8% of its detected quadrilateral overlaps an 8 px expanded speech-balloon mask (previously 25% of the eroded interior mask). Measuring the actual slanted text polygon avoids false overlap from empty corners of its axis-aligned box. External lettering is rendered across the detected box, so the expanded guard reduces the chance of writing over the balloon outline; it still needs visual measurement. Saved OCR advances to pipeline version 17.
- Nearby vertically stacked external text lines can now group across gaps up to twice the OCR line height when they share the same horizontal column, preserving caption and title context. Bubble grouping is unchanged; the OCR pipeline has advanced and this grouping change still needs visual review.
- External caption grouping no longer stops scanning as soon as a newer column is vertically distant. OCR lines from adjacent columns can interleave, so the early stop could split a valid multi-line caption even when its own previous line was nearby. New OCR runs use the corrected grouping; saved pages are not forcibly invalidated, preserving existing OCR and translation reviews. The grouping fix is not yet visually verified.
- External OCR now also deduplicates overlapping-tile detections when their boxes nearly coincide and their recognized text is strongly similar, retaining the higher-confidence read. This aims to prevent two OCR variants of one caption from overlapping and both being skipped during rendering. It applies to new OCR runs without invalidating saved reviews and has not yet been visually verified.
- Bubble OCR retries uncertain crops once with CLAHE local-contrast enhancement and keeps the result with more usable detections, using confidence as a tie-breaker. Clear bubbles stay on the original single-pass path. Saved OCR is not invalidated; the retry's accuracy and added latency have not been measured.
- The local model adapter removes known output wrappers such as code fences and an `Arabic translation:` prefix before validating and storing generated text. It does not paraphrase or replace model content; runtime impact and model output variants have not been tested.
- Bubble font fitting now checks candidate glyphs using small per-line masks and allocates the full bubble mask only once for the chosen layout. Rendering advances to pipeline version 8 so an old visual preview is not silently reused after the layout change; OCR and reviewed translations are retained. Runtime and visual effects have not been measured.
- External-text overlap review now sorts boxes by horizontal position and skips disjoint vertical spans, avoiding polygon comparisons for clearly distant regions. The overlap threshold and rendering decisions are unchanged; the runtime gain has not been measured.
- Long-chapter progress polling now reads saved statuses directly instead of recalculating every page's dialogue-context freshness every two seconds. Freshness remains recalculated when opening, translating, rendering, exporting, or explicitly pausing a chapter; the expected database-work reduction has not been measured.
- MangaDex search and chapter discovery run through its public API. Chapter metadata displays MangaDex and scanlation group attribution. The local exclusion list can hide chapters from selected scanlation groups and reject their direct chapter links; entries can be removed from the web interface and are not synchronized automatically.
- Source discovery is capability-based: the UI can select a source and uses common search/chapter routes. MangaDex search includes all origins but lists English chapters only. ManhuaPlus.org is an experimental mixed-catalog HTML adapter and accepts works with an explicit Manga, Manhwa, or Manhua type; the user must choose continuous vertical scrolling for the current workflow. Sources are independently implemented; no Kotatsu/Kotatsu Redo parser code or binaries were copied. Kotatsu Redo's parser collection is GPL-3.0 and is listed in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).
- Local chapter import accepts JPEG, PNG, WEBP images, or CBZ archives, stores pages plus series identity in the SQLite-backed library, remembers the last read page, supports chapter-title and series-name edits, sequential page translation with pause/resume at bubble boundaries, and rendering a full chapter before exporting CBZ with `ComicInfo.xml`. Re-importing a chapter from the same source reuses its saved local copy instead of downloading duplicate page files. Remote source links and available publisher/scanlation credits are kept in the library, shown in the reader, and included in exports. Chapters can be archived and restored without deleting images or translation data; the full library state can also be exported in one backup ZIP without model weights. Pages with no OCR text or with every region intentionally excluded are kept unchanged in the rendered edition. Existing previews are reused when their reviewed text and inclusion settings still match; edited pages invalidate their previous preview until redrawn. MangaDex imports retain their stable manga ID; local imports can set a series title, and existing chapters can be linked to a local series name from the reader to share reviewed translations.
- Region review now provides a per-region locator that scrolls the matching OCR box itself to the center of the viewport and highlights it, making low-confidence bubble and external-text corrections easier on tall manhwa pages. This interaction has not yet been browser-verified.
- When local translation fails on one region, completed regions and OCR remain saved, the failed region and short error are recorded, and the reader keeps its review controls visible with a resume prompt. Retry continues from saved work. This recovery display has not been browser-verified.
- Resumed local pages now skip every explicitly excluded OCR region instead of spending model inference on text the reviewer chose not to include. Region progress uses one running completion count rather than rescanning the full page after each generated line, avoiding quadratic counting work on dense pages. This behavior has not been runtime-tested or benchmarked.
- Chapter-wide preview readiness now treats absent or malformed saved OCR-region arrays as not ready instead of dereferencing them and stopping the reader UI. This matches the server's incomplete-page guard; browser behavior has not been verified.
- An empty or non-Arabic result can no longer silently count as a completed region in local chapters or direct-source pages. Human-edited text must also contain Arabic letters to count as a translation; an English string must be explicitly excluded before preview. Chapter progress counts only usable translations, resumes missing included regions, and server-side guards prevent incomplete pages from being rendered or exported as translated CBZ. Correcting an excluded region skips model inference and clears stale output for a future re-inclusion. A no-text page can reach the unchanged-original preview path without trying to index a missing OCR list. These safeguards have not been runtime-tested yet.
- Concurrent OCR/translation requests and page mutations (review edits, single-region retranslation, and rendering) share a temporary per-page lock. Repeated requests reuse saved work, and reviewer edits cannot race an active page write. This concurrency behavior has not yet been load-tested.
- First-use initialization of the shared RapidOCR adapter and the Index/TranslateGemma router is protected by a process lock. Simultaneous requests no longer race to create duplicate model objects or separate llama servers on the same port. This initialization path has not been concurrency-tested.
- Chapter progress labels now distinguish external-text/bubble detection from dialogue translation and count OCR regions rather than calling every region a bubble.
- Each chapter-region record stores its own translation latency (and failed-attempt latency), including a failed single-region retry. The direct-source page review also displays the time for successful and failed single-region retries. These timings are cleared when automatic text is invalidated by a model/context change and refreshed on retry, so an old run is not presented as the new one. This helps identify slow lines separately from total page time during later profiling; it has not yet been measured on a representative chapter.

This exposes the existing hybrid decision to reviewers; display behavior still needs browser verification.

This cache contains model output, not hand-authored translations; naturalness and cross-chunk continuity still need review.

Exact sentence overrides and human-reviewed translations are no longer returned as automatic answers; glossary terms can still guide names and terminology, and model-generated translations can still be reused from the context-scoped cache. A confirmed human translation from an earlier region may guide context and terminology, but is not returned as the current answer. Index's prompt prioritizes complete, natural Arabic and only permits concise phrasing when it preserves every source meaning; its current recipe is v13. Saved pages refresh under translation context version 18, while explicit edits already on a page remain preserved.

Its official format treats the text field as the content to translate; putting dialogue context or glossary entries there would make them translation input. The model card notes that custom post-edit prompting is unsupported; a Google model-team reply recommends application-level terminology handling. No context behavior is claimed for this adapter. The request uses the completed prior dialogue from earlier pages and the nearby bubbles, then invalidates the old rendered preview so stale Arabic is not exported. After successful retranslation on a current completed page, it refreshes that page's context signature, allowing dependent later pages to be identified as stale on their next freshness check.

Text detection, deduplication, and rendering use crop-relative masks; long pages no longer allocate one full-page bitmap per detected balloon. The OCR pipeline version was advanced so saved pages are reprocessed with the new detector behavior.
- Manhwa external-text OCR now avoids tiny trailing edge tiles: near-full pages are handled as one resized tile, while long pages finish with a full-context tile. The OCR change has not been measured or visually checked yet.

This reduces translation of mixed-script OCR noise in the English-source phase. Saved page OCR is invalidated through pipeline version 9. The precision/recall tradeoff has not been measured.

This avoids shrinking an entire webtoon into a narrow detector input; very long pages may require extra detector passes, and this path still needs runtime and visual review.

Remote rendered PNGs use a process-owned temporary directory with a 512 MiB/8-preview LRU, so large previews do not remain resident in RAM and are removed when the server exits.

Only matching terms are sent to context-aware local engines. Glossary changes get a distinct translation-memory scope so old outputs are not reused under changed terminology. Human-reviewed translations are saved with work, glossary, and dialogue-context scope. ## Windows setup

For a phone on the same private Wi-Fi, set `MANGA_BIND_HOST` to the computer's private IPv4 before running `tools/run_web.ps1`; the launcher prints the matching URL. The app rejects wildcard and public bind addresses and does not edit Windows Firewall.

The local server accepts only loopback hostnames and the configured private IPv4 address. Browser write requests must have a matching same-origin `Origin` or `Referer`, protecting local import and library APIs against cross-site form submissions and DNS-rebinding hostnames. Keep the server on trusted local networks; it is not an authenticated public service.

Local llama.cpp tuning uses project-scoped environment variables: `MANGA_LLAMA_THREADS` (defaults to detected logical CPUs, bounded at 8), `MANGA_LLAMA_THREADS_BATCH` (defaults to the same value), `MANGA_LLAMA_CTX_SIZE` (defaults to 4096 for CPU and 3072 for the CUDA launcher), `MANGA_LLAMA_PARALLEL` (defaults to 2 request slots), and `MANGA_TRANSLATION_WORKERS` (defaults to 2 independent regions per page). The CUDA launcher's 3072-token context is divided across its two slots (1536 tokens per request) to retain GPU memory headroom. Translation prompts, source context, model, and decoding policy remain unchanged. For a serial comparison, set both parallel/worker values to `1` before starting the processes.

`MANGA_LLAMA_GPU_LAYERS` defaults to `0` for the regular CPU server; `MANGA_LLAMA_DEVICE` selects devices only for builds that support it. The CUDA candidate is separate and not selected automatically. Start it explicitly with `.\.venv\Scripts\python.exe tools\start_index_cuda_server.py`; on this 2 GiB GPU it defaults to 6 layers and accepts the tuning variables above. Six layers used about 1.7 GiB during the two-slot benchmark; eight layers peaked near 1.97 GiB and are not the default due to limited memory headroom. Older Vulkan inference failed on NVIDIA with `device lost`; Vulkan on Intel fell back to staged host memory, and OpenVINO graph execution failed on a feature-map mismatch.

The repeatable `tools\benchmark_index_concurrency.py` check compared four fixed dialogue prompts on a two-slot CUDA server. At the conservative 6-layer setting, serial inference took 68.34 seconds and two-way requests took 62.72 seconds (1.09× throughput); all four outputs were identical to the serial counterparts and contained Arabic. At 8 layers and a 3072-token context the sample reached 1.209× throughput (67.18 versus 55.57 seconds), but VRAM peaked at 1,972 of 2,048 MiB, so that setting is not the default on this device. These are small benchmarks, not a full-chapter speed guarantee. Individual bubbles may take longer while requests overlap; chapter throughput improves modestly. Validate on other devices and chapter types before changing these settings; arbitrary chapters and phones cannot be promised a fixed completion time.

Index inference logs include llama.cpp prompt-processing and token-generation times and rates when the server returns timing data. The active local llama.cpp build enables prompt caching by default. No model, prompt, or generation-quality settings are changed by the parallel request setting.

## Checks

Run the model regression checks with:

```powershell
.\.venv\Scripts\python.exe -m pytest translator_engine\tests
```

The benchmark runs the active Index model by default and writes a new report. Add `--include-translategemma` only after TranslateGemma's access terms are accepted and its weights are installed:

```powershell
.\.venv\Scripts\python.exe -m translator_engine.benchmark_matrix
```

Add `--include-challenge` to include the extra 20-item dialogue/narration challenge suite. Its proposed Arabic references are explicitly marked `draft_needs_human_review`; they are intended to broaden manual review and must not be treated as gold translations or as a model-quality score.

Each run creates a new JSON report under `translator_engine/data/benchmark_runs/`; it preserves the raw translations, end-to-end timing, available llama.cpp prompt/generation token rates, and blank human-review fields. The report distinguishes first-request wall time (including lazy model startup) from the mean of later successful requests. Per-inference llama.cpp timing fields help compare warm requests. Script-ratio and exact-string checks are diagnostics, not measures of semantic accuracy.

After local OCR and translation, review each detected dialogue bubble and edit OCR or Arabic text when needed. The renderer uses one fitted font size for each bubble. It uses the system Arial font on Windows; set `MANGA_ARABIC_FONT` to a TrueType Arabic font file to change it. Export includes originals, stored translations, and any generated rendered previews.

The regression suite checks model loading, local decoding, Arabic-script output, English dialogue samples, local OCR on the provided page image, local-library workflows, glossary/memory behavior, and Arabic rendering. It does not replace human review or certify full-chapter translation quality. Add a licensed, reproducible translation model bundle before redistributing the existing OPUS-MT assets.

## OCR update (2026-11-11)

RapidOCR PP-OCRv6 small remains the primary text reader.
